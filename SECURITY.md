# Security policy

[简体中文](SECURITY.zh-CN.md) | English

Do not report suspected vulnerabilities in public issues. Contact the repository maintainers
privately and include the affected revision, host platform, configuration, impact, and a minimal
reproduction without secrets or personal data. Maintainers should acknowledge a report, triage it,
prepare coordinated fixes for affected component repositories, and publish remediation guidance
only after users have a reasonable upgrade path.

Supported releases are the revisions pinned by the current manifest release branch. Unpinned
development worktrees and historical snapshots receive no security support.

See the detailed [security model](doc/SECURITY.md) for trust assumptions and deployment hardening.
